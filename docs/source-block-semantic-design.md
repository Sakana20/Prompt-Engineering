# 真人原文块语义适配与校验设计

## 问题

真人原句只有在原本的品类、消费需求和语义角色中才成立。当前逻辑只校验
`source_block_id`、改写锚点和字数，没有校验“原文块是否适合当前商品”和
“插槽值是否仍是商品内容”。因此会出现：

- 咖啡、奶茶等饮品承接“你不饿”“人是铁饭是钢”等正餐逻辑；
- 平台、配送、红包和津贴被填入“加、再加、外加”等商品组成插槽；
- “都给你配好了”的回指对象从套餐、小料或配菜滑向了活动信息；
- 品牌、商品名和主商品内容重复，主次关系不清。

## 设计原则

1. 先判断品类和消费需求，再选择原文块；不允许先选块再强行套商品。
2. 整块直接填槽属于低自由度操作；只有原文块合约与当前商品完全匹配时才能
   使用 `source_fill`。
3. `human_rewrite` 可以借用不同品类原文的非品类性字眼和说话逻辑，但最终
   需求、动作和回指对象必须与当前商品一致。
4. 商品事实和活动事实分层。平台、红包、津贴、券、配送和行动引导不得填入
   商品名、套餐组成、搭配、小料、配菜、口感或食用动作插槽。
5. 每批 `human_rewrite` 固定为 `floor(N/2)`；其余条目优先使用兼容 `source_fill`。
   兼容块或商品资料不足时，使用不登记真人来源的 `natural_generate` 补足，不阻断整批任务。

## 原文块合约

每个块需要登记以下元数据：

- `source_block_id`；
- 适用品类族；
- 语义需求，例如饱腹、解馋、套餐组合或分享；
- 直接填槽前必须已确认的资料；
- 插槽语义类型；
- 禁止出现在商品插槽中的活动角色。

当前原文库中：

- `learn-001-combination` 只适用于资料中确实有主商品、搭配、小料、配菜或套餐
  组成的任务。“加、再加、外加、都给你配好了”的对象必须全是商品内容。
- `learn-005-not-hungry` 只适用于能直接承接饱腹或用餐需求的正餐、快餐或固体食品；
  咖啡、奶茶、果茶、果汁等饮品不得直接填槽。
- 其他当前带有“吃、夹着吃、一口下去、食用动作”的原文块默认属于固体食品直填块。
  饮品可在 `human_rewrite` 中参考其非品类性字眼，但成稿必须改成“喝”及真实
  饮用需求，不得保留饱腹论证。

## 生成与审查流程

1. 从任务资料区分品牌、商品名、品类、已确认商品事实和活动事实。
2. 将品类归入最小必要的品类族；当前至少区分“饮品”与“固体食品/正餐”。
3. 按原文块合约过滤 `source_fill` 候选；再检查当前资料是否能填满必需插槽。
4. `source_fill` 在清单中登记 `source_slot_values`，只列出实际填入方括号的已确认
   商品事实。活动信息不得出现在该字段。
5. 原文块商品段成立后，再用独立句子衔接当前 `CampaignSpec`；不得把活动词塞进
   原文块的并列结构。
6. 生成后先做语义关系审查，再运行 CLI 校验。任何逻辑问题或确定性校验问题都必须
   修改并重新校验。

## 确定性校验

`validate-batch`、`package` 和 `export-csv` 必须执行：

- 原文块 ID 必须存在于固化库；
- 饮品的 `source_fill` 不得使用固体食品专用块；
- 饮品成稿不得出现“你不饿”“人是铁饭是钢”“一顿不吃”等饱腹逻辑；
- 新清单中 `source_fill` 必须登记非空 `source_slot_values`，且每个值确实出现在成稿中；
- `source_slot_values` 不得包含平台、红包、津贴、券、配送、链接或行动引导；
- `learn-001-combination` 的“加、再加、外加、配好了”关系中不得夹入平台或
  活动信息；
- 现有字数、利益点、季节、实时天气、原文锚点、去重和画面 Prompt 校验继续执行。
- `natural_generate` 的 `source_block_id`、`source_slot_values` 和
  `rewrite_anchor_phrases` 必须为空。

旧清单没有 `source_slot_values` 时保持可读；新清单由 `init-batch` 显式创建空数组，未填写
就不能通过批量校验。确定性规则只覆盖可靠识别的硬冲突；更开放的语义自然度仍由
Codex 在生成后执行主谓宾、需求—商品、并列层级和回指关系审查。

## 验收标准

- “瑞幸咖啡”或“咖啡”使用 `learn-005-not-hungry` + `source_fill` 时校验失败。
- 咖啡、奶茶成稿保留饱腹句时，无论是哪个轨道都校验失败。
- `learn-001-combination` 把“配送到家”“淘宝闪购”“红包”或“津贴卡”填入
  `source_slot_values` 时校验失败。
- 活动信息被写入“加、再加、外加、都给你配好了”的并列关系时校验失败。
- 套餐组成值全部来自当前已确认商品资料，活动句独立衔接时，上述新校验通过。
