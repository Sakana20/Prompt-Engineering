# Prompt Engineering 接入飞书 H3 任务表方案

日期：2026-09-11
阶段：本地合同与 CLI 已实现；尚未执行线上写入
目标 Base：`自动化视频生产队`
目标数据表：`AI视频批量任务`（`tblDA5s4ZIBzpDaF`）
目标视图：`表格`（`vewVEjpYEB`）

## 1. 结论

建议保留现有 CSV 作为下游文件交接格式，并把飞书多维表格实现为 Prompt Engineering 的一个
独立 **H3 队列镜像适配器**。同一次发布操作继续生成原格式 CSV，同时为 CSV 中每条任务生成
Dreamina 首帧图、下载到本地，再创建一条飞书草稿记录。飞书不是新的语义源、审计主表或
H3 API 客户端。

推荐链路：

```text
用户确认的商品/活动事实
  → Codex 生成文案与视频 Prompt
  → generated-task-batch 审计清单
  → validate-batch 确定性校验
  → Dreamina 按 person_prompt 生成每条任务的首帧图
  → 等待资源成功并下载到本地
  → 协调发布
      ├─ 按现有合同写出原格式 CSV
      └─ 上传已下载的首帧图并写入飞书“草稿”记录
  → 人工复核
  → 显式批准后改为“待生成”
  → 外部 H3 worker 领取、生成、回写状态与成品
  → Prompt Engineering 只读同步任务结果索引
```

关键安全边界：**创建飞书记录只允许写成“草稿”；把记录改成“待生成”是独立的付费/执行
动作，必须再次获得用户明确确认。** 不提供“落表即待生成”的默认入口。

本阶段确认的飞书默认值为：时长 `15` 秒、画面比例 `9:16`、分辨率 `720p`、生成数量 `1`；
生成类型固定为“首帧图生视频”。提交人固定为用户本次指定的飞书账户。

## 2. 表格现状（只读调研）

### 2.1 结构与工作方式

- Base 时区为 `Asia/Shanghai`，当前不是高级权限 Base。
- 表格共有 29 个字段，主字段为“任务名称”。
- 指定视图展示全部 29 个字段，没有持久化筛选、排序或分组。
- Base 中另有一个仪表盘和一个“工作流” Block；工作流当前为 `disabled`，且 `steps=[]`。
  因此不能假设 Base 内置工作流负责 H3 发配，实施前需要确认真正的外部 worker、触发条件与
  接口所有者。
- 当前表单入口与同一数据表共用字段，但本方案不依赖表单提交。

### 2.2 历史数据特征

本次完整读取了目标视图的 1,466 条记录，读取范围完整（`has_more=false`）：

| 维度 | 现状 |
|---|---|
| 提交状态 | 已完成 1,190；草稿 222；已取消 49；排队中 2；待生成 1；空值 2 |
| 生成类型 | 文生视频 1,430；首尾帧图生视频 19；多参考图视频 10；首帧图生视频 5；空值 2 |
| 时长 | 15 秒 1,455；5 秒 9；空值 2 |
| 分辨率 | 720p 1,444；1080p 20；空值 2 |
| 画面比例 | 绝大多数为 9:16 |
| 生成数量 | 非空记录均为 1 |
| 成品 | 1,190 条“已完成”记录均有成品视频；成品图片字段全部为空 |
| 参考图 | 首帧图 24 条；人物/场景/产品参考图合计命中 15 条记录，整体使用率低 |
| Prompt | 最长 6,212 字符，平均约 1,305 字符 |

最近一组 20 条 1080p 文生视频记录呈串行处理特征，单条约 4 分 50 秒至 5 分钟。该观察只能
作为容量规划提示，不能据此宣称 H3 的固定耗时或并发能力；并发、限流和额度保护应由外部
H3 worker 管理。

### 2.3 当前表结构风险

1. “提交状态”单选项中除正常状态外，还出现 `15`、空字符串以及两段超长视频 Prompt；
   这是明显的字段污染，实施前应人工确认并清理选项，但本阶段不修改。
2. “画面比例”单选项中出现 `15`；“分辨率”单选项中出现 `9:16`，疑似历史错列写入。
3. “错误信息”在 1,466 条记录中全部为空，包括已取消记录，无法支持失败分类、自动重试和
   运营排障。
4. “父记录”当前全部为空，“生成数量”实际均为 1，说明父子拆单模型尚未投入使用。
5. 54 条非完成记录已有“平台任务编号”，因此平台编号只能表示“平台已受理或曾受理”，不能
   作为生成成功判据。
6. 当前视图没有筛选。worker 如果扫描整表，必须在服务端按“提交状态=待生成”下推过滤，并
   使用稳定游标/幂等键，不能每轮全表扫描后在内存判断。

## 3. 责任边界

### 3.1 Prompt Engineering 负责

- 从用户确认的事实生成和校验文案、人物/首帧 Prompt、H3 视频 Prompt；
- 生成稳定 `task_id`，保留一对一审计映射；
- 按现有 10 列合同写出 CSV，不改变既有 CSV 字段、路径和下游兼容性；
- 通过官方 `dreamina-canvas` CLI，使用 `seedream_4.0` 按每条任务的 `person_prompt` 生成首帧；
- 验证 Dreamina 资源终态后下载图片，记录文件大小与 SHA-256；
- 把同一批已校验任务及首帧图片镜像到飞书；
- 在写入前验证表、字段类型、枚举值、附件引用和重复任务；
- 只写“草稿”，并在独立批准动作后将指定草稿切换为“待生成”；
- 只读同步飞书的 record ID、平台任务编号、状态、进度、错误与结果附件索引。

### 3.2 外部 H3 worker 负责

- 领取“待生成”记录并原子声明任务；
- H3 鉴权、模型调用、额度保护、限流、重试和轮询；
- 把平台任务编号、进度、错误、开始/完成时间及成品视频回写飞书；
- 对不确定提交进行平台侧查重，避免重复扣费；
- 管理真实媒体上传和 H3 可访问的临时资源。

Prompt Engineering 不保存 H3 Cookie、Token、签名 URL 或真实业务凭据，也不自行绕过平台
风控。未经明确确认，不触发 H3 付费生成。

## 4. 建议的字段合同

### 4.1 现有字段映射

| 飞书字段 | 上游来源 | 写入阶段 | 规则 |
|---|---|---|---|
| 任务名称 | `task.title` + 稳定 `task_id` | 草稿创建 | 必填；与 CSV `task_id` 一一对应 |
| 项目名称 | `batch.task_name` | 草稿创建 | 必填 |
| 提交状态 | 适配器控制 | 两阶段 | 创建固定为“草稿”；批准时才改“待生成” |
| 生成类型 | 固定值 | 草稿创建 | 固定为“首帧图生视频” |
| 提示词 | `avatar_prompt` | 草稿创建 | 使用完整视频 Prompt；去除 `NO_SPLIT` 控制标签，保留完整口播 |
| Negative Prompt | H3 任务配置 | 草稿创建 | 可选；仅使用已确认模板，不从历史记录反推 |
| 时长（秒） | 固定值 | 草稿创建 | 固定为 `15` |
| 画面比例 | 固定值 | 草稿创建 | 固定为 `9:16` |
| 分辨率 | 固定值 | 草稿创建 | 用户口径“720”规范化为表格枚举 `720p` |
| 生成数量 | 固定值 | 草稿创建 | 固定为 `1`，批量任务拆成一记录一生成 |
| 随机种子 | 空值 | 草稿创建 | 首版留空，不伪造 |
| 首帧图片 | Dreamina 下载结果 | 草稿创建 | 每条任务必填且恰好 1 张；只上传已验收的本地文件 |
| 尾帧图片 | 空值 | 草稿创建 | 首版不写 |
| 人物/场景/产品参考图 | 空值 | 草稿创建 | 首版不写；商品参考仅用于 Dreamina 首帧生图时的视觉约束 |
| 运营备注 | 审计摘要 | 草稿创建 | 写 task ID、内容指纹、schema/模板版本等非敏感信息 |
| 平台任务编号 | H3 worker | 执行回写 | Prompt Engineering 不预填 |
| 实际任务数 | H3 worker | 执行回写 | 首版应为 1 |
| 生成进度 | H3 worker | 执行回写 | 建议标准化为 `0%`–`100%` |
| 错误信息 | H3 worker | 执行回写 | 应写稳定错误码 + 人类可读摘要，禁止写凭据 |
| 成品视频/图片 | H3 worker | 执行回写 | H3 结果附件；完成状态前必须通过存在性校验 |
| 开始/完成时间 | H3 worker | 执行回写 | 使用 Base 时区或带时区时间 |
| 提交人 | 用户指定账户 | 草稿创建 | 运行时唯一解析并使用 user open_id 写入；open_id 不写入仓库 |
| 父记录 | 暂不启用 | - | 首版一记录一任务，不建立父子拆单 |

### 4.2 CSV 合同保持不变

CSV 继续使用当前 `write_oceanengine_csv(...)` 的 10 列合同：

```csv
task_id,person_prompt,script,aspect_ratio,voice,title,notes,reference_image_uri,reference_image_url,reference_image_pid
```

不得为飞书/H3 修改列顺序、字段含义、`NO_SPLIT` 清洗、notes 规则、UTF-8 原子写入或拒绝覆盖
行为。Dreamina 生成并下载的首帧图片只进入本地任务目录和飞书“首帧图片”栏，不追加到现有
CSV 列。

CSV 与飞书写入属于一次协调发布，但无法跨本地文件系统和飞书实现真正的数据库事务。发布
回执必须分别记录 `csv_written`、`dreamina_submitted`、`first_frame_downloaded`、
`attachment_uploaded` 和 `draft_created`，失败后按 task ID + 内容指纹及原 Dreamina 提交身份
恢复，不能重写已有 CSV、重复扣取生图积分或重复创建飞书记录。

### 4.3 审计字段策略

首版不要求修改现有 29 个字段。把 `task_id`、批次 ID、schema/模板版本和内容指纹以结构化、
非敏感摘要写入“运营备注”，同时保存到本地发布回执。

如果后续确认外部 worker 会忽略未知字段，再考虑把以下内容提升为独立字段：

| 字段 | 类型 | 用途 |
|---|---|---|
| 上游任务ID | 文本 | 保存 `task_id`，作为跨系统幂等键；建议唯一 |
| 上游批次ID | 文本 | 关联同一 generated-task-batch |
| 上游Schema版本 | 文本 | 记录 batch/interface schema 版本 |
| Prompt模板版本 | 文本 | 追踪语义模板版本 |
| 内容指纹 | 文本 | 对规范化输入做 SHA-256，用于查重和不确定提交恢复 |
| 模型 | 单选或文本 | 明确为 H3，避免未来多模型共表时混淆 |
| 审批时间 | 日期时间 | 记录从草稿切换待生成的时间 |
| 审批人 | 用户 | 记录付费发配责任人 |
| 错误码 | 文本 | 与“错误信息”分离，支持稳定分类和重试策略 |
| 重试次数 | 数字 | 由 worker 更新；不靠历史备注推断 |

当前阶段不新增字段，避免在未确认 worker 行为时影响已有生产链路。

## 5. Dreamina 首帧生成与下载合同

每条通过批次校验的任务都必须先生成一张首帧图片：

1. 使用现有、已校验的 `person_prompt` 作为首帧语义来源，不从历史表格 Prompt 反推人物；
2. 使用当前 CLI 实时解析得到的 canonical model `seedream_4.0`，画面比例固定 `9:16`，数量固定
   `1`；模型当前要求分辨率为 `2K` 或 `4K`，首版默认使用非会员档 `2K`，不得静默切换 4K；
3. 无商品参考图时使用 `t2i`；有当前任务自己的商品参考图时使用 `i2i`，仅引用本任务资产以
   保持商品外观，不得跨任务复用；当前 `seedream_4.0` 的 `i2i` 支持 1–6 张图片引用；
4. 图片 Prompt 必须在当前模型 2,000 字符上限内；创建/编辑节点时显式传 mode、model、ratio、
   resolution 和 count；
5. 首帧继续遵循项目现有静态人物图规则：9:16、固定中景、直视镜头、人物约占画面二分之一、
   商品在人物前方桌面、人物不手持/不看/不接触商品、非商品区域无 logo、无字幕；
6. 每个批次使用最小充分画布结构：一批可共用一张画布，每条任务一个独立图片节点，不为了
   流程完整额外创建主体、时间轴、音频或视频节点；
7. 在任何运行副作用前保存稳定的 canvas/project ID、Node ID、update ID 和逐条 submit ID。
   报价不等于授权；服务端要求积分确认时，先向用户展示逐条与总报价，取得明确批准后才能运行；
8. 运行后使用原 submit ID 等待同一次操作进入终态，不因超时或响应丢失更换 ID 重跑；
9. 只有 operation 终态成功且存在可用图片 Resource ID，才允许选定该资源。受理、返回任务号
   或资源数组非空都不能替代终态校验；
10. 使用 `dreamina-canvas resource download` 把选中的图片下载到任务目录，检查返回字节数、
    SHA-256 和实际图片格式；零字节或格式异常不得交付飞书；
11. 下载文件命名必须包含稳定 task ID，下载结果、Node ID、submit ID、Resource ID、文件大小和
    SHA-256 进入本地发布回执；不得保存短期积分凭证、签名 URL 或 provider payload；
12. 图片生成或下载失败则该任务不创建飞书记录；同批其他任务默认继续完成可恢复处理，并在
    回执中标记失败；
13. 下载文件上传成功后，飞书“首帧图片”必须恰好 1 张，“生成类型”固定为“首帧图生视频”；
14. Dreamina 首帧生图不等于 H3 视频生成。H3 仍须等待记录从“草稿”被明确切换为“待生成”。

首版不使用尾帧、多参考图和参考视频模式；这些字段保持为空。

上述 `seedream_4.0` 只用于“CSV 同步飞书 H3 草稿”的首帧生成，不修改项目现有独立
Dreamina Canvas 任务包的图片模型候选或视频节点合同。

## 6. 状态机与幂等

建议状态机沿用现有枚举，但收紧写入权限：

```text
草稿 --人工批准--> 待生成 --worker领取--> 导入中/排队中 --> 生成中 --> 已完成
  |                    |                         |          |
  +----人工取消------> 已取消 <------------------+          +--> 失败
```

规则：

1. Prompt Engineering 只创建“草稿”，不得直接创建“待生成”。
2. 批准命令只接受明确的本地批次 ID 和精确 record ID 集合；不允许按模糊任务名批量提交。
3. `上游任务ID + 内容指纹` 相同且已有非终态记录时拒绝重复创建。
4. 已有平台任务编号的记录禁止自动重提；先由 worker 查询平台真实状态。
5. “已完成”必须同时满足：进度 100%、完成时间非空、至少一个成品视频/图片存在。
6. “失败”是否可自动重试由错误码白名单决定；未知错误默认人工处理。
7. 状态回退、取消和重试必须保留审计事件，不覆盖原平台任务编号。

## 7. Codex 编排、CLI 与模块设计

Dreamina 首帧必须由 Codex 当前会话按 `dreamina-canvas-cli` Skill 调用官方 CLI 生成和下载。
Python 生产代码不得自行拼接 Dreamina HTTP 请求、接入其他模型 API 或保存模型凭据。对用户
表现为一次“生成 CSV 并同步飞书草稿”的工作流，内部仍保持三层分工：

```text
Codex（语义与 Dreamina 编排）
  ├─ 调用项目 CLI 做批次校验和原格式 CSV 写入
  ├─ 通过 dreamina-canvas CLI 逐条生成、验收并下载首帧
  └─ 调用飞书能力上传下载文件并创建草稿记录

Prompt Engineering CLI（确定性）
  ├─ validate-batch / 现有 CSV writer
  ├─ 渲染飞书记录草稿清单
  └─ 校验字段合同、默认值、指纹和发布回执

飞书/H3 worker（外部执行）
  └─ 仅领取已人工切换为“待生成”的记录
```

建议新增领域模块，不把飞书字段转换散落到 CLI：

```text
src/avatar_prompt_pipeline/
├── h3.py                  # H3 草稿任务 dataclass 与固定默认值
├── feishu_h3.py           # Base 字段绑定、草稿清单、回执和状态读取
└── cli.py                 # 命令入口
```

建议增加确定性辅助命令；真正的 Dreamina 生成、下载与飞书写入仍由 Codex 按 Skill 工作流
编排：

```bash
# 只读：校验本地任务并渲染待双写计划，不写 CSV、不生图、不写飞书
avatar-prompts preflight-feishu-h3 \
  --input <generated-task-batch.json> \
  --interface <feishu-h3-interface.json>

# 确定性输出飞书草稿清单；首帧资产位置由 Codex 生图后回填
avatar-prompts render-feishu-h3-drafts \
  --input <generated-task-batch.json> \
  --interface <feishu-h3-interface.json> \
  --output <feishu-h3-drafts.json>

# 校验 Codex 完成双写后的 task_id → CSV/图片/record_id 回执
avatar-prompts validate-feishu-h3-receipt \
  --receipt <publish-receipt.json>
```

`feishu-h3-interface.json` 保存 Base/table/field ID、固定默认值、提交人运行时绑定键和执行
边界，以及 Dreamina `seedream_4.0 + t2i/i2i + 9:16 + 2K + count=1` 的首帧配置；不保存
提交人的 open_id、用户 token 或其他个人数据。发布时通过运行时配置或飞书通讯录唯一解析用户
指定账户；零命中或多命中均停止写入。
`publish-receipt.json` 保存批次指纹、task ID、Dreamina 公开恢复身份、下载文件 SHA-256、飞书
record ID、创建时间和当时的 schema revision，采用 UTF-8 原子写入且拒绝覆盖。

状态切换和只读同步优先直接使用飞书能力，按发布回执中的精确 record ID 操作。若后续证明
需要可复用的本地命令，再增加 `submit-feishu-h3` 和 `sync-feishu-h3`；无论采用哪种入口，
切换“待生成”都必须是独立高风险动作。

## 8. 附件策略

飞书 attachment cell 保存的是 Base 文件 token，不是 H3 可直接访问的永久 URL。首版建议：

1. 本地任务只保存稳定资产键或受控本地路径，不把签名 URL 写入审计清单；
2. 草稿发布时由飞书适配器上传图片并取得 attachment token；
3. H3 worker 领取记录后下载附件或换取平台可访问资源；
4. 临时 URL 只在执行内存中存在，不写仓库、不写运营备注；
5. 每个 task 只能引用自己的资产登记，禁止按文件名猜测或跨记录复用；
6. 上传成功但记录写入失败时，要记录孤儿附件清理清单，不能静默丢失。

## 9. 分阶段实施计划

### Phase 0：接口确认

- 已核对本机 `dreamina-canvas` CLI 1.0.0：`seedream_4.0` 支持 `t2i`/`i2i`、9:16、2K/4K，
  count 范围 1–8；实际执行前仍须重新查询实时目录；
- 确认外部 H3 worker 的负责人、触发字段、轮询间隔、并发、限流和额度门禁；
- 获取 H3 首帧图生视频的实时 Prompt 长度、图片格式、15 秒、9:16 和 720p 合同；
- 确认“待生成”是否立即触发付费，以及草稿修改是否会被 worker 误取；
- 确认现有异常枚举的清理窗口。

交付：签字确认的字段合同和状态机；未确认前不实施写入。

### Phase 1：领域合同与只读预检

- 新增不可变 H3 task/interface/binding 模型；
- 保持现有 CSV 和 generated-task-batch 必填合同不变，以已校验 `avatar_prompt` 作为 H3 提示词；
- 实现 Base URL 解析、字段 ID 绑定、类型/枚举/schema revision 校验；
- 实现固定默认值、提交人唯一解析、重复 task ID、内容指纹、Prompt 长度和首帧存在性校验；
- 首先只提供 `preflight-feishu-h3`。

交付：不写飞书的预检报告及单元/集成/e2e 测试。

### Phase 2：CSV + Dreamina 首帧 + 飞书草稿协调发布

- 继续调用项目现有 CSV writer 写出原格式 CSV；
- Codex 通过官方 Dreamina CLI 使用 `seedream_4.0`、9:16、2K、count=1 生成首帧；
- 按实时报价和积分门禁等待用户确认，保存逐条 submit ID，生成完成后选择成功资源；
- 下载首帧到本地并验证字节数、SHA-256 和图片格式；
- 下载验收通过后上传附件并创建飞书记录，状态强制为“草稿”；
- 固定写入 15 秒、9:16、720p、生成数量 1、首帧图生视频和用户指定提交人；
- 分任务记录 CSV、Dreamina 节点与提交、下载图片、飞书附件和草稿创建阶段，保留部分成功
  回执，支持安全恢复；
- 写出 task ID → CSV 行/Dreamina 资源/下载文件/飞书 record ID 回执。

交付：保持原 CSV 的可恢复双写能力；飞书只出现草稿，不触发 H3。

### Phase 3：批准与发配

- 用户在 CSV、首帧和飞书草稿全部审阅完成后，明确告知可提交；
- 提交前重新读取记录，确认仍为草稿、指纹未变化、首帧恰好 1 张且固定参数未被改坏；
- 只把本次明确批准的精确 record ID 集合改为“待生成”；
- 禁止按整个视图、模糊任务名或项目名批量切换状态。

交付：显式批准后发配；默认路径仍停在草稿。

### Phase 4：只读同步与恢复

- 同步状态、平台任务编号、进度、错误码、时间和结果附件索引；
- 输出本地审计报告，不自动下载结果、不自动重试；
- 对“平台编号存在但状态不确定”的任务交由 H3 worker 查重恢复。

交付：跨系统可追踪闭环。

### Phase 5：小流量验证

- 先生成 1 条原格式 CSV、1 张 Dreamina 首帧，下载并验收后创建 1 条飞书草稿；
- 明确批准后只运行 1 条 H3 样片；
- 验收 Prompt 遵循度、人物/商品一致性、台词完整性、声音、口型、字幕、时长、比例、清晰度；
- 样片通过后再做 3–5 条串行批次，验证幂等、取消、失败和恢复；
- 未确认真实并发与额度前，不开放大批量自动发配。

## 10. 测试与验收

### 10.1 自动化测试

- 单元测试：字段映射、生成类型判定、状态机、指纹、Prompt/枚举/附件校验；
- 集成测试：mock 飞书读取、原 CSV writer 调用、草稿清单、部分失败回执、重复发布和 schema
  漂移；Dreamina CLI 在自动化测试中使用受控假实现，不发起真实生图或积分消费；
- e2e：默认离线，覆盖 preflight、CSV 保持原格式、草稿发布 dry-run、显式提交门禁和只读同步；
- golden case：首帧图生视频成功例，以及异常枚举、缺首帧、重复任务、平台编号已存在等失败例。

### 10.2 上线验收

- 任何创建动作默认状态均为草稿；
- 未显式批准不能出现待生成记录；
- CSV 仍为现有 10 列合同，飞书同步不得改变 CSV 内容；
- 每条飞书草稿都有且只有一张对应 task ID 的 Dreamina 下载首帧；
- 每张首帧均由实时解析的 `seedream_4.0` 以 9:16、2K、count=1 生成，资源终态成功，且本地
  下载文件字节数、SHA-256 和格式已验证；
- 每条草稿均为 15 秒、9:16、720p、生成数量 1、首帧图生视频和用户指定提交人；
- 同一 task/content 指纹重复运行不会产生第二条可执行任务；
- 字段改名或类型/枚举变化时预检失败，不做部分写入；
- 成功记录可从 task ID 追踪到飞书 record ID、平台任务编号和结果附件；
- 失败记录有稳定错误码，不泄露 token、Cookie、签名 URL 或个人数据；
- 仓库完整通过 Ruff、mypy strict、pytest；Skill 结构变化时通过 `quick_validate.py`；
- 代码/CLI/Schema/Skill 变更完成后，按仓库规则备份并同步安装本地 Skill，目录比对无差异，
  已安装 CLI 能看到新增命令。

## 11. 实施前待确认项

以下信息不能从当前表格可靠推断，进入实施前必须补齐：
